📝 Submission Format

To encourage broad participation while respecting teams' intellectual property, we allow action-based submissions in early phases. Code submissions will be required in later phases to ensure reproducibility and scientific integrity.

Participants may submit their results in one of the following two formats depending on the Phase I:

  1. Code Submission (submission.zip): For full reproducibility, participants can submit a single submission.zip archive that will be executed inside the evaluation Docker container. The archive must follow the structure below: 
    submission.zip
├── run.sh                   # Entry point script (must be executable)
├── config.yaml              # YAML config for inference (optional)
├── model.pth                # Pretrained weights (optional)
├── custom_policy.py         # Your custom policy or inference logic (optional)
├── ...
    The evaluator will unzip your archive and call ./run.sh. Your script must generate predictions at output/result.json, which will be generated defaultly by falcon_evaluator.py and parsed to compute scores.
  2. Action Submission (actions.json): For Minival and Phase I, participants may alternatively submit a pre-generated action sequence file actions.json. This file will be generated by falcon_evaluator.py and evaluated with replay_evaluator.py inside the container to compute scores. The evaluator will automatically execute: 
    
python -u -m habitat_baselines.eval --config-name=falcon_hm3d_replay.yaml

⚠ Important: For Phase II, only full code submission (submission.zip) will be accepted. We will verify reproducibility and may request additional audits for top-performing teams on both test phases.

🧱 Evaluation Docker Image

We provide a standardized Docker environment to ensure consistency and reproducibility across all submissions. The Docker image used for evaluation depends on the competition phase:

  • Phase I: Evaluations use docker pull zeyinggong/robosense_socialnav:v0.5
  • Phase II: Evaluations will use docker pull zeyinggong/robosense_socialnav:v0.7

Participants are strongly encouraged to use these images for local development and testing to ensure compatibility with the remote evaluation environment. We recommend using the Minival Phase for testing, as submission attempts in the main phases are limited. You can also refer to the Baseline ZIP Example for packaging your submission.

Docker Image Changes in v0.7

The v0.7 image introduces several key changes to the evaluation environment:

  1. Driver Compatibility: Fixed EGL driver compatibility issues.
  2. Multi-Environment Support: Phase II now supports up to 8 environments, including single-environment inference.
  3. Updated Action Space: The action space has been refined to provide more precise control. The new action space is fully backward-compatible with Phase I.
    • 0 - stop — now correctly ends the episode
    • 1 - move_forward
    • 2 - turn_left
    • 3 - turn_right
    • 4 - move_backward — newly added action for moving backward
    • 5 - pause — newly added action for pausing without movement

⏱ Evaluation Time: The Minival Phase typically completes evaluation within 5-10 minutes. The Phase I evaluation may take approximately 3-5 hours depending on the queue length and inference runtime. The Phase II evaluation may take approximately 2-4 hours 2–4 hours, depending on the number of environments used for inference, queue length, and inference runtime. If your submission remains in the "Running" state for more than 48 hours, please contact us at robosense2025@gmail.com for assistance.

📊 Result Format

Our baseline uses habitat_baselines.eval to run simulation and inference, then automatically generates a result file at output/result.json. The file contains the final scores in the following format: 

{
  "SR": 0.50,
  "SPL": 0.50,
  "PSC": 0.50,
  "H-Coll": 0.50,
  "Total": 0.50
}

Participants are free to implement their own pipeline as long as run.sh produces a valid result.json at the expected location. However, note that all submissions must run actual inference and simulation within the container. Any submission found to bypass the evaluation logic or produce a fabricated result.json without executing the intended inference and simulation pipeline will be disqualified.

📁 Dataset Mounting and Access Policy

To simplify evaluation, we use a fixed minival mount point inside the evaluation Docker container: 

/app/Falcon/data/datasets/pointnav/social-hm3d/minival

Internally, our backend automatically mounts the appropriate dataset for each phase onto this path. This means your code only needs to read from this single location regardless of which phase is being evaluated.
